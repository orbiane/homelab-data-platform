# ADR-008: 作業は NEXT.md に定義し、自律ループが実装して PR を出す。持ち主はマージで承認する

- 日付：2026-11-08
- 状態：採用（持ち主の判断、2026-11-08）

## 状況

- これまでの進め方：会話のセッション（claude.ai のチャット）が作業の指示を書き、持ち主がそれを手元の Claude Code に貼り、承認の画面で1つずつ承認し、報告をチャットに貼り返した。持ち主が機械の前にいないと進まず、往復のたびに待ちが生まれた
- 段階2・3で、仕組み（権限の規則、hook、git の hook）で止めたことは守られ、お願い（CLAUDE.md）はときどき破られた（ADR-007 の状況）
- 定時に Claude Code を起こし、決めた作業を進めて PR を出させる形（自律ループ）は、別の個人のリポジトリで既に回っている（観察：持ち主の別プロジェクト。このリポジトリでは未検証）

## 決定

1. やることは、すべて `NEXT.md` に書く。1行1作業。中身は `docs/orders/` の指示書。状態は `ready` / `attended` / `owner` / `in-pr` / `done` / `blocked`
2. 持ち主の機械で、定時に Claude Code を起こす（自律ループ）。1回の起動で `ready` の1件だけを進め、作業ブランチ `auto/<ID>` に push し、PR を作る。手順は `docs/agent/loop.md`
3. **マージが持ち主の承認になる。ループはマージしない。** 断るときは PR を閉じる
4. 決めごと（設計判断、正解、定義の数え方、データの作り直し）は、ループは決めない。`owner` の行にして止まる。持ち主の決めごとは、チャットが `NEXT.md` と ADR に書く
5. `main` への変更は、すべて PR を通す（ループも、持ち主の見ているセッションも、チャットも）

## 仕組みで止めること（L0 で作る）と、お願いで頼むこと

| | 仕組み（強制） | お願い（文書） |
|---|---|---|
| ループにできることを絞る | 承認の画面を出さないモード（`dontAsk`）と、ループ専用の権限の表。表に無いことは自動で断られる | loop.md の「やらないこと」 |
| マージしない、`main` に push しない | 権限の表の deny と、push の行き先を `auto/*` だけにする hook。GitHub の ruleset で `main` への直接の push を止める | loop.md、CLAUDE.md |
| 定義・決定メモ・守りそのものを変えない | ADR-007 の関所（そのまま）。ループでは承認が出ないので、ask は断られる | CLAUDE.md の守ること2 |
| 1回に1件、止まるときに止まる | 起動の台本（同時に1つ、1日の上限、時間切れ、開いた PR が3つ以上なら始めない） | loop.md |

## 理由

- 持ち主が機械の前にいなくても進む。持ち主の手間は「マージする／閉じる」と「決めごとを一言」になる
- 承認の場所を、1つずつの操作から PR の単位に移す。どこで承認したかが git に残る
- 決めごとをループに渡さない線は、段階3の結果に基づく（書かなければ、エージェントが自分で決めた）

## 代わりに失うもの

- 1つずつの操作を、持ち主が承認の画面で見なくなる。見るのは PR の差分と報告だけになる
- 承認の重みが、マージのボタン1つに集まる。中身を読まずにマージすれば、エージェントが自分で書いたものを自分で通す形になる（ADR-007 の H5 と同じ形）
- 段階2で、人の目は値が合って数え方が違う答えを見落とした。PR の点検をチャット（同じ系統のモデル）に頼ると、点検する側も独立していない

## 採らなかった案

- 今までどおり、持ち主が指示を貼って1つずつ承認する：一番安全だが、持ち主が機械の前にいないと進まない
- ループに自動でマージさせる：人の承認がどこにも残らない
- GitHub Actions で動かす：warehouse と `mf` が持ち主の機械にしか無い
- クラウドのセッションから持ち主の機械のシェルを使う：観察では、そのシェルは機械の上の別の環境（Linux）で、macOS 用の道具を動かせない

## 知っている穴（塞いでいない）

- K1 持ち主とループは、GitHub の同じアカウントを使う。GitHub の側では、マージしたのが持ち主かループかを区別できない。マージを止めているのは、ループの側の権限の表と hook だけ
- K2 ループは `uv run python` を許されているので、スクリプトの中では何でもできる（ADR-007 の H2 と同じ）。コミットの入口の関所（R6）と、PR を見る人が最後の関所
- K3 権限の規則は、コマンドの文字で当てる。書き方の揺れで抜けるものは、hook で補う（L0 の試しで確かめる）
- K4 定時の起動は、持ち主の機械の Claude のログインに頼る。切れると黙って止まる（記録で気づく）

## 見直すとき

- ループの PR を、持ち主が中身を読まずにマージしていると分かったとき
- 止めるはずのものをループが通したとき（すぐ止めて、L0 の試しに足す）
- ループの費用が、持ち主の決めた上限を超えたとき
