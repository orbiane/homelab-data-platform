# L1 の仮決め

L1 は持ち主が見ているセッションで進めた。持ち主がその場で決めたことは、ここではなく報告（`docs/agent/reports/L1.md` の 3）に書いた。

## L1-1 続きの回の ID は、ブランチ名の auto/ の後ろ

- 日付：2026-11-17
- 決めたこと：`pick.py` が決め・直し・途中で選んだときの ID は、PR のブランチ名から `auto/` を外したもの（`auto/L1-trial` なら `L1-trial`）。報告のファイルもその名前（`docs/agent/reports/L1-trial.md`）
- ほかの案：NEXT.md の表の ID（`L1-trial` なら `L1`）に丸める。指示書の試し2が「`L1-trial` の続きを選ぶ」と書いているのと合わず、同じ ID の PR が2つあると、どちらの続きか分からなくなる
- 選んだ理由：続きは PR 1つに結びつく。ブランチ名がそのまま push の行き先（`git push -u origin auto/<ID>`）になり、ループの権限の表を変えずに済む
- 止まる類ではないと判断した理由：選び方の実装で、定義・データ・守りではない
- 戻すときに直す所：`agent/loop/pick.py` の `choose_next`、`agent/loop/review_checks.py` の `task_id_of`

## L1-2 「途中」の印は、本文の最初の行（先頭の HTML のコメントと空行を除く）

- 日付：2026-11-17
- 決めたこと：PR の本文の先頭の HTML のコメント（複数行も）と空行を飛ばし、最初の行の `#` を外したものが「途中」で始まれば、途中の PR とする。ループが途中で終わるときは、報告の見出しを `# 途中：<ID> の報告` にする（loop.md の 3 を直した）
- ほかの案：本文の1行目を文字どおり見る。ループの PR の本文は報告のファイル（`--body-file`）で、1行目は必ず公開リポジトリの注意書きのコメントになり、決して当たらない（L0 の報告の 9 に書かれていた）。報告に専用の状態の行を足す案は、報告の形（10項目）を変えることになる
- 選んだ理由：報告の形を変えずに、見出しの行1つで表せる
- 止まる類ではないと判断した理由：選び方の実装
- 戻すときに直す所：`agent/loop/pick.py` の `body_status_line`、`docs/agent/loop.md` の 2 と 3

## L1-3 「決め：」（全角のコロン）も数える

- 日付：2026-11-17
- 決めたこと：1行目の先頭が `決め:` か `決め：` なら、持ち主の決めとして数える
- ほかの案：半角のコロンだけ。日本語の入力では全角のコロンになりやすく、持ち主の答えが黙って読み落とされる
- 選んだ理由：読み落としの方が、読みすぎより害が大きい（読みすぎは、続きの回で「あいまい」として止まれる）
- 止まる類ではないと判断した理由：持ち主の答えを受け取る形の実装で、決めの中身には触れない
- 戻すときに直す所：`agent/loop/pick.py` の `DECISION_PREFIXES`、`docs/agent/loop.md` の 2

## L1-4 台本のレビューは「記録にあること」と「1行目の形」の両方で数える

- 日付：2026-11-17
- 決めたこと：レビューのコメントとして数えるのは、台本が `gh pr comment` で出したときに `~/homelab-loop/logs/reviews.jsonl` に残した URL にあり、かつ1行目が `レビュー: <判定>（<短い ID>）` のものだけ
- ほかの案：(a) 1行目の形だけ。同じアカウントの誰でも同じ形を書ける（指示書の試し3が、まさにこれを数えないことを求めた）。(b) 記録だけ。出したあとに GitHub の画面で本文を書き換えられても気づけない
- 選んだ理由：指示書の「台本が付けた1行目の形と、台本が出したコメントの記録で決める」の両方を取った
- 止まる類ではないと判断した理由：指示書が「決め方は仮決めしてよい」とした所
- 戻すときに直す所：`agent/loop/pick.py` の `is_script_review`・`load_records`

## L1-5 機械の確かめで「直しが要る」に決めるのは 1・2・3・5・6

- 日付：2026-11-17
- 決めたこと：変わってはいけない場所、`NEXT.md`、報告の見出し、bank のコミット、個人情報のどれかが見つかったら、モデルが「マージしてよい」と返しても「直しが要る」にする。4（仮決めの欄の欠け）は表に出すだけで、判定はモデルに任せる
- ほかの案：review.md の文字どおり 1 だけ。2・5・6 も決まり（ADR-009 の決定4・6、CLAUDE.md の守ること5）で、モデルの見落としで通すと困る。4 は書き方の揺れ（欄の名前の違い）で当たりやすいので、強制にはしなかった
- 選んだ理由：決まりに書かれた「してはいけない」は機械で止め、書き方の揺れは人とモデルの目に任せる
- 止まる類ではないと判断した理由：レビューの判定を厳しくする方向だけ
- 戻すときに直す所：`agent/loop/review_checks.py` の `MUST_FIX`、`docs/agent/review.md` の 3

## L1-6 モデルの返事の形が違えば「持ち主の決めが要る」

- 日付：2026-11-17
- 決めたこと：返事の1行目が `判定: マージしてよい|直しが要る|持ち主の決めが要る` でなければ、判定は「持ち主の決めが要る」にして、返事はそのまま本文に載せ、台本の注を足す
- ほかの案：コメントを出さずに次の回でやり直す。同じ先頭のコミットで費用がかさみ、持ち主には何も見えない。「直しが要る」にする案は、ループが何を直すか分からない
- 選んだ理由：分からないときは持ち主に返す（ADR-009 の「迷ったら止まる類」と同じ向き）
- 止まる類ではないと判断した理由：判定を弱めない
- 戻すときに直す所：`agent/loop/review_checks.py` の `build_comment`

## L1-7 同じ引き金のあとに続きの回を始めていれば、もう選ばない

- 日付：2026-11-17
- 決めたこと：決めのコメント・直しのレビュー・途中（最後のコミット）のそれぞれについて、その時刻より後に、同じ PR で同じ種類の続きの回を `runs.jsonl` の `start` に記録していれば、選ばない
- ほかの案：引き金だけで選ぶ。続きの回が何もコミットせずに終わると（断られて止まる、あいまいで止まる）、毎時同じ PR を選び続け、1日の上限8件を使い切る
- 選んだ理由：引き金1つに続きの回1回。同じ引き金で2回目が要るなら、持ち主が新しいコメントを書く
- 止まる類ではないと判断した理由：選び方の実装
- 戻すときに直す所：`agent/loop/pick.py` の `tried_since`

## L1-8 続きの回のあと、台本が PR の本文を報告で置き換える

- 日付：2026-11-17
- 決めたこと：続きの回が終わったら、`run.py` がブランチの最新の `docs/agent/reports/<ID>.md` を読み、`gh pr edit --body-file` で PR の本文にする
- ほかの案：(a) ループの表に `gh pr edit` を足す。守りを広げる（止まる類）。(b) 置き換えない。本文の「途中」が消えず、3回まで同じ PR を選び続け、持ち主も古い本文を読む
- 選んだ理由：ループの表を変えずに、本文と報告をそろえられる。台本は PR にコメントを出すのと同じ GitHub の書き込みをもう持っている
- 止まる類ではないと判断した理由：権限の表は変えない。台本が書くのは、ループ自身の PR の本文だけ。迷う所なので、報告の 9 にも書いた
- 戻すときに直す所：`agent/loop/run.py` の `sync_pr_body`、`agent/loop/prompt.md` の続きの節

## L1-9 レビューは、1件を選ばなかった回もやる。作業場所を PR の先頭に乗せる

- 日付：2026-11-17
- 決めたこと：ロックと時間帯（JST 01:20〜03:30）と作業場所の確かめを通った回は、ループの1件の有無にかかわらずレビューの段をやる。1日の上限（8件）には数えない。ループの回のあと作業場所が汚れていたらやらない。1つずつ作業場所を PR の先頭（detached）に乗せ、終わっても戻さない（次の回の `prepare_worktree` が `origin/main` に戻す）。同じ先頭のコミットで2回失敗したらやめる
- ほかの案：ループが1件を進めた回だけ。今のように開いた PR が3つで新しい行を選ばない間は、レビューが一度も走らない
- 選んだ理由：レビューを待つ PR は、ループが止まっている間ほど溜まる
- 止まる類ではないと判断した理由：定時の仕組み（launchd の設定・時刻）は変えない。1回の起動の中の順番だけ
- 戻すときに直す所：`agent/loop/run.py` の `main`・`run_reviews`・`review_one`

## L1-10 コメントを出す前に、全文に個人情報の検査を当てる。表を折りたたんで付ける

- 日付：2026-11-17
- 決めたこと：台本が組み立てたコメントの全文に、base の `.githooks/scan.sh` の検査を当て、当たったら出さずに `failed` を記録する。本文の下に機械の確かめの表（`<details>`）と、台本が出したことの1行を付ける。機械の確かめの表には、個人情報の行の場所と種類だけを出し、行の中身は出さない
- ほかの案：モデルへの頼みで書かないように頼むだけ。公開のリポジトリで、コメントはコミットの hook を通らない
- 選んだ理由：コミットと同じ物差しを、コメントにも当てる
- 止まる類ではないと判断した理由：書き込みを狭める方向だけ
- 戻すときに直す所：`agent/loop/run.py` の `review_one`、`agent/loop/review_checks.py` の `scan_text`・`to_markdown`・`build_comment`

## L1-11 続きでブランチに乗せるとき、手元の同じ名前のブランチが origin と違えば止まる

- 日付：2026-11-17
- 決めたこと：`git switch -C <ブランチ> origin/<ブランチ>` の前に、手元のブランチがあって origin と違えば、乗せずに `stop` を記録する
- ほかの案：いつも origin に合わせる。worktree は持ち主のふだんの作業場所とブランチを共有するので、持ち主の手元にだけあるコミットを、黙って捨てることになる
- 選んだ理由：消える変更を作らない
- 止まる類ではないと判断した理由：止まる向きだけ
- 戻すときに直す所：`agent/loop/run.py` の `checkout_branch`
