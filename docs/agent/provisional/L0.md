# L0 の仮決め

L0 は持ち主が見ているセッションで進めた。持ち主がその場で選んだこと（ループの起動では `--setting-sources user` で読む、起動の台本を作業場所の外に写して起こす、hook に `onFailure: block` を足す、L0 の PR は Claude がマージしてよい）は、仮決めではないので、ここには書かず報告（`docs/agent/reports/L0.md`）に書いた。

## L0-1 据え付けの台本 `agent/loop/install.py` を足した

- 日付：2026-11-09
- 決めたこと：作業場所を作る（worktree と symlink）、symlink を info/exclude に足す、守りの写しを作る、plist を書く、の4つを台本にした。launchctl は打たない
- ほかの案：README に手で打つコマンドだけを書く。打ち間違えやすく、symlink の向きや PATH を書き写すときに、ホームの絶対パスがリポジトリに入りやすいので選ばなかった
- 選んだ理由：同じ手順を何度でも同じように打てる。`--dry-run` で中身を先に見られる
- 止まる類ではないと判断した理由：定時の仕組みそのもの（読み込み）は持ち主が手で行い、台本は書くだけにした
- 戻すときに直す所：`agent/loop/install.py`、`agent/loop/README.md` の据え付け方

## L0-2 ループの関所の範囲を、指示書より少し広げた

- 日付：2026-11-09
- 決めたこと：指示書の P（push）・G（gh）・D（dbt）に加えて、push と同じ働きをする `git send-pack`・`git subtree push`、git の別名（設定にあるもの、`-c alias.x=...`）、gh の `alias`・`extension`、パスで呼ぶ `launchctl`・`mf`・`duckdb`（X）を止める。`sh -c`・`eval`・`$( )`・`xargs`・`find -exec`・`timeout` などの中のコマンドも読む
- ほかの案：指示書の文字どおり P・G・D だけ。権限の表の deny は文字で当たるだけなので（ADR-008 の K3）、別名やパスで呼ぶ形が残る
- 選んだ理由：どれも「止めると決めたものを、別の書き方で通す」形で、K3 を hook で補うという指示書の 2 の趣旨に入る
- 止まる類ではないと判断した理由：守りを弱める方向ではなく、狭める方向だけ。持ち主の見ているセッションで、試しの表と一緒に示した
- 戻すときに直す所：`.claude/hooks/loop_guard.py`、`agent/loop/tests/loop_guard_cases.py`（B10〜B12・B14〜B16・B19〜B23・B29・B39〜B41）

## L0-3 ループの表の deny を、指示書の一覧より足した

- ほかの案：足さない。`.claude/` と `--settings` のファイルは Claude Code 自身が `dontAsk` で断る（protected paths）が、`agent/loop/` と `NEXT.md` は守られない
- 選んだ理由：`NEXT.md` と `docs/decisions/README.md` を作業の PR が書き換えない（ADR-009 の決定6）を、お願いではなく仕組みにする。`agent/loop/` は起動の台本そのもの。`Read` を名前だけで allow にした（指示書どおり）ので、作業場所の外の認証情報を読む道を塞いだ
- 止まる類ではないと判断した理由：狭める方向だけ

## L0-4 PR が2本以上ある ID の状態：マージされた PR があれば済み

- 日付：2026-11-09
- 決めたこと：`pick.py` の `status_of`。マージされた PR があれば済み、無くて開いた PR があれば進行中、閉じた PR だけなら断られた
- ほかの案：マージ＋開いた PR を進行中にして、後ろの行を待たせる。続きの PR が放っておかれると、後ろの作業が止まり続ける
- 選んだ理由：loop.md の「済み：PR がマージされている」を文字どおりに取った。続きの作業は別の行として起こす決まり（loop.md の 3）なので、同じ ID の開いた PR は追加の直しとして扱える
- 止まる類ではないと判断した理由：作業の選び方の実装で、定義・データ・守りではない
- 戻すときに直す所：`agent/loop/pick.py` の `status_of` と selftest。PR #3（L1、同じブランチで直しを続ける決まり）がマージされたら、L1 で見直す

## L0-5 作業場所の symlink を、git の info/exclude で見えなくする

- 止まる類ではないと判断した理由：持ち主の機械の git の設定だけで、リポジトリの中身は変えない

## L0-6 定義のファイルの Edit を、ループの表では deny にした

- 日付：2026-11-09
- 決めたこと：`Edit(**/_metrics.yml)`・`Edit(**/_semantic_models.yml)`・`Edit(./dbt_project/models/**)` を deny に入れた
- ほかの案：ADR-007 の関所だけに任せる。関所は、HEAD にある決定メモのパスを書いた定義の Edit を通し、そのあとをプロジェクトの表の ask に任せる。ループはプロジェクトの表を読まず `Edit(./**)` が allow なので、メモのパスを書けば定義を書き換えられてしまう
- 選んだ理由：ADR-008 の表は「ループでは承認が出ないので、ask は断られる」としているが、その ask はループに読み込まれない。プロジェクトの ask にあたるものを deny にすると、ADR-008 の意図どおりになる。`dbt_project/models/` の下は、定義（名前の違うファイルを含む）と既存の staging・mart の数え方で、どちらも loop.md の止まる類。NEXT.md のループの行に、ここを書き換える作業は無い
- 止まる類ではないと判断した理由：狭める方向だけ
- 戻すときに直す所：`.claude/loop-settings.json`、`agent/loop/tests/check_loop_settings.py` の6

## L0-7 `--permission-prompts none` を起動に足した

## L0-8 起動の台本が作業場所を origin/main に戻し、ID を選ぶ。`--only` は依存を見ない

- 日付：2026-11-09
- 決めたこと：`run.py` は、作業場所が汚れていなければ `git fetch` して `origin/main` に detached で戻し、`pick.py` で ID を決めてから Claude を起こす。前置き（`prompt.md`）で「選び直さない」と伝える。`--only <ID>` は種類 `loop` と PR なしだけを見て、依存は見ない
- ほかの案：loop.md のとおり、モデルが fetch して選ぶ。指示書は「モデルに選ばせない」ので、選ぶのは台本にした。`--only` が依存を見ると、L0 のマージ前に M2 を回せない（指示書の 6 は、マージ前に M2 を回す）
- 選んだ理由：守りのファイルと作業の始まりを、持ち主がマージした版にそろえる
- 止まる類ではないと判断した理由：loop.md の選び方の規則そのものは変えず、選ぶ場所を台本に移しただけ。loop.md の差分を同じ PR に入れた
- 戻すときに直す所：`agent/loop/run.py`、`agent/loop/prompt.md`、`docs/agent/loop.md` の 1 と 2

## L0-10 基準データの実体の場所を `--add-dir` で渡す

- 日付：2026-11-10
- 決めたこと：`run.py` が、作業場所の `data_generation/output`（symlink）の実体のパスを、起動のときに解決して `--add-dir` で渡す
- ほかの案：(a) 権限の表に `Bash(cd data_generation/output && shasum -a 256 -c ../output.sha256)` を足す（M2 の1回目の報告が推した案）。つないだコマンドは、`cd` の部分が承認の要る `cd` のままなので、効くかが説明書から読み取れない。(b) 作業場所の中に本物のディレクトリを作り、ファイルごとの symlink にする。指示書の「symlink にする」から外れ、新しいファイルが見えない
- 選んだ理由：説明書（permissions の Read-only commands）に「作業場所か追加の作業場所の中への cd は読むだけの扱い」とある。追加の作業場所への書き込みは、Edit の allow（`./**`）に当たらないので `dontAsk` で断られる。試し x14・x15 で確かめた
- 止まる類ではないと判断した理由：読める場所が1つ増えるだけで、書ける場所は増えない（試しで確かめた）。ただし権限の届く範囲を変えるので、PR の点検で見てほしい
- 戻すときに直す所：`agent/loop/run.py` の `claude_cmd`、`docs/analysis/loop/l0_trials.md` の x14・x15

## L0-11 前置きと loop.md に、ループの書き方の決まりを足した

- 日付：2026-11-10
- 決めたこと：PR は `gh pr create ... --body-file docs/agent/reports/<ID>.md` で作る。Bash は1回の呼び出しに1つのコマンドで打つ。照合のあとは作業場所の根に `cd` で戻る。push は `git push -u origin auto/<ID>` の形
- ほかの案：権限の表を広げて、本文を直接書く `gh pr create` や、つないだコマンドを通す。表の文字の規則は、複数行や記号を含むコマンドを読み切れずに断るので、広げても確実には通らない
- 選んだ理由：M2 の1回目と2回目で、実際にこれらで断られた（`docs/analysis/loop/l0_m2_first_run.md`、PR #5 の報告の6）
- 止まる類ではないと判断した理由：権限は変えず、書き方を伝えるだけ
- 戻すときに直す所：`agent/loop/prompt.md`、`docs/agent/loop.md` の 1 と 6。PR #3（L1）の「本文の1行目が『途中』なら続きを選ぶ」と合わない（本文が報告のファイルそのもので、1行目は見出し）。L1 で合わせる
