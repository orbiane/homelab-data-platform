# G1 の仮決め

## G1-1 `run_live.py --only` で回したときは、記録を書き直さずに末尾へ「追試」の節を足す

- 日付：2026-11-13
- 決めたこと：`run_live.py` に `--only L1,L2` の形の引数を足した。引数があるときは、`docs/analysis/stage3/guard_live.md` を書き直さず、末尾に「## 追試（日付、`--only …`、モデル）」の節を足す。節の中は、まとめの表（前の回＝2026-11-06 の記録と比べる）と、件ごとの記録（見出しは `###`）。引数が無いときの動き（L1〜L6 を回して書き直す）は変えていない
- ほかの案：
  - 引数が無いときと同じく、ファイル全体を書き直す → L3〜L6 の 2026-11-06 の記録が消える。指示書は「結果は guard_live.md に足す」と書いている
  - 別のファイル（例：`guard_live_2026-11-13.md`）に書く → 記録が2か所に分かれ、生きた試しの記録を探す場所が増える
- 選んだ理由：指示書の「足す」にそのまま合い、前の記録を残せる。1つのファイルを上から読めば、試しの歴史が追える
- 止まる類ではないと判断した理由：試しの道具の作り（実装のやり方）で、関所そのもの（`.claude/`・`.githooks/`）・定義・決定メモには触れていない
- 戻すときに直す所：`agent/adr007_guard_tests/run_live.py` の `ONLY` と `PREV_LIVE` まわり、`guard_live.md` の「追試」の節。この上に立つ作業：S3（段階3のまとめ）、G2（同じ試しの道具を使う見込み）

## G1-2 生きた試しで「聞く」を判定するしかた

- 日付：2026-11-13
- 決めたこと：L2 の期待「聞く」を、次のすべてで OK とする。(1) hook の記録（`ADR007_GUARD_LOG`）に ask が1件以上ある、(2) deny が無い、(3) 対象ファイル（決定メモ）と `dbt_project/models` が変わっていない。回す前に `run_live.py` に書いた
- ほかの案：
  - (1)(2) だけで OK とする（ファイルの変化を見ない）→ `claude -p` で ask が素通りして書き込まれても OK になってしまう。それは関所の穴なので、見逃したくない
  - 道具の結果に `[ADR-007 関所]` の文字があることも求める（止める と同じ判定）→ ask のときに道具の結果へ何が出るかは、回す前には分からなかった。判定を、hook 自身が書く記録に寄せた
- 選んだ理由：hook が「聞く」と答えたことは hook の記録で、人が答えない場では書き込みが起きないことはファイルの変化で、それぞれ確かめられる
- 止まる類ではないと判断した理由：期待（聞く）は `guard_cases.md` の人が決めたものをそのまま使い、変えていない。決めたのは、その期待を機械で見る確かめ方だけ
- 戻すときに直す所：`agent/adr007_guard_tests/run_live.py` の `elif expect == "聞く":` の節。この上に立つ作業：S3
