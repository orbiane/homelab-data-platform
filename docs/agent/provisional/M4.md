# M4 の仮決め

## M4-1 staging は mart で代わりに数え、raw は CSV をシェルで数える

- 日付：2026-11-14
- 決めたこと：指示書は「staging と raw の両方を MCP の道具 `run_sql` で数える」。しかし staging（`main_staging.stg_revenue_monthly`）は CSV を読むビューで、`run_sql` はファイル操作が止められているためエラーになった。raw は DB の中に無い。そこで次の形にした
  - staging の代わりに、staging の写しの `main_mart.fct_revenue`（テーブル）を `run_sql` で数える
  - raw は、リポジトリの中の `data_generation/output/revenue_monthly.csv` を `cut | sort | uniq` で数える（読むだけ）
- ほかの案：
  - A. 止まって持ち主に聞く：指示書の道具では数えられない、と報告だけを出す。数え方を決めるのは止まる類ではないので、止めるほどではないと判断した
  - B. `dbt` で staging をテーブルにして作り直す：`warehouse.duckdb` への書き込みになり、止まる類（基準データ）に当たる
  - C. Bash で `duckdb` を打って CSV を読む：CLAUDE.md の環境の落とし穴で禁止されている
- 選んだ理由：`fct_revenue.sql` は staging の列を選ぶだけで、where も distinct も無い。行の数は CSV と同じ 183 だった。raw は CSV そのものを文字列で数えるので、DB を通らない別の数え方になり、mart の結果との突き合わせにもなる
- 止まる類ではないと判断した理由：数え方の道具の選び方で、定義・汚れの扱い・staging の数え方・基準データのどれも変えていない。書き込みは無い
