# S3 の仮決め

## S3-1 下流の `ctr` の行を「今を説明するもの」と「過去の記録」に分け、今の側をさらに3つに分ける

- 日付：2026-11-17
- 決めたこと：
  - 今を説明するもの：README.md、CLAUDE.md、NEXT.md、`agent/` の下、`dbt_project/` の下、`docs/analysis/regression/` の下のうち `results/` を除くもの（試験の道具・bank・SQL・README）、ADR-006 の「基準値」の節（115 行目）
  - 過去の記録：それ以外のすべて（`docs/analysis/` の記録、`regression/results/`、`docs/agent/`、`docs/orders/`、`docs/business/`、ADR-006 の「背景」の節（62 行目）を含む ADR）
  - 今の側の行を、(a) 今の指標として名前を使う、(b) 経緯として書いた（「ctr から直した」「廃止」など）、(c) ファイル名（決定メモ・指示書）の中にだけ出る、の3つに分ける。`-ctr-` というファイル名の一部を説明している行（`regression/README.md:15`、`check_docs.py:102`）は (c) に入れた
- ほかの案：
  - R1 の文書の層と同じ4つの文書だけを「今を説明する文書」とする → 試験の道具と NEXT.md が過去の側に入り、G1 で直した「関所の試しに名前が残っていた」件が、今の側の数に表れない
  - 分けずに全体の件数だけを出す → 指示書が「分けて数える」と書いている
- 選んだ理由：今も動いているもの（定義・道具・試験）と、その時点を書き残したもの（記録）で線を引くと、名前が残ると困るのはどちらかが分かる。R1 の文書の層の範囲との差も示せる
- 止まる類ではないと判断した理由：文書の中の数え方で、定義・決定メモ・汚れの扱い・基準データ・守りのどれにも触れない
- 戻すときに直す所：`docs/analysis/governance-design.md` の 5 の「下流」。この上に立つ作業：無し（ビルドの段の最後の作業）

## S3-3 本文の「数字」は値だけを数え、一覧は報告に置く

- 日付：2026-11-17
- 決めたこと：成功の条件の「本文の数字の一覧」で数えるのは、件数・割合・金額・本数・回数などの値だけ。日付・時刻、ID（ADR-007、H1、T21、R3、B3、r1 など）、コミットの番号、節や行の番号は数えない。一覧は、本文の長さの目安（4,000 字前後）を守るため、`governance-design.md` ではなく報告（`docs/agent/reports/S3.md` の2）に置く
- ほかの案：
  - 数字の形をしたものをすべて数える → ID と日付が大半になり、出どころを確かめる意味が薄れる
  - 一覧を文書の末尾に付ける → 文書が長くなり、初めて読む人には要らない
- 選んだ理由：記録に無い数字を書かない、という決まりが守るのは値。日付と ID は、それ自体が出どころを指している
- 止まる類ではないと判断した理由：報告の書き方の決めで、ほかのファイルには触れない
- 戻すときに直す所：`docs/agent/reports/S3.md` の2の数字の一覧
