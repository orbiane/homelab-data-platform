## R1-1 bank は JSON 1本と、問ごとの SQL ファイルに分ける

- 日付：2026-11-13
- 決めたこと：`docs/analysis/regression/bank.json`（13問の配列、字下げあり）に、問ごとの欄と期待値を書く。SQL の本文は `sql/<ID>.sql` に置き、bank からファイル名で指す
- ほかの案：(1) 指示書の例の `bank.tsv`。SL の呼び出し（リスト・入れ子）と複数行の SQL を1つのセルに入れると、読めない・差分が見にくい。(2) JSON Lines。1問1行なので、長い SQL と期待値の表が1行に詰まり、期待値の変更の差分がどこか分かりにくい
- 選んだ理由：期待値を変えたときの git の差分が、その値の行だけになる。SQL はそのまま DuckDB の文として読める
- 止まる類ではないと判断した理由：試験の作り方（ファイルの置き方）で、定義・決定メモ・汚れの扱いに触れない。指示書が「形は任せる」と書いている
- 戻すときに直す所：`bank.json`、`sql/`、`run_numbers.py` の読み込み。上に立つ作業：R2、W1、R3、V3

## R1-2 `run_numbers.py` は、server の環境に無い Python で起動されたら自分を起動し直す

- 日付：2026-11-13
- 決めたこと：`import mcp` に失敗したら、`uv run --frozen --project agent/sl_mcp python <自分>` で起動し直す（`.mcp.json` が server を起動するのと同じ形）。README の回し方は `--project agent/sl_mcp` の形で書いた
- ほかの案：(1) `agent/sl_mcp/.venv` の site-packages を `sys.path` に足す。起動した Python と版が違うと、pydantic_core などの拡張が読めない。(2) MCP のクライアントとして stdio で server を起動する（check.py の条件1〜6の形）。指示書は「import して呼ぶ（check.py と同じ形）」で、check.py も busy・maintenance の確かめでは関数を直接呼んでいる
- 選んだ理由：ループの権限の表で通る形は `uv run python ...` だけで、リポジトリの直下には Python の依存の一覧が無い。起動し直す先は server と同じ環境で、新しい権限を足していない
- 止まる類ではないと判断した理由：権限の表は変えていない。起動し直しで使うのは、`.mcp.json` が毎回使っている環境と同じ。ただし「権限の表に書いた形の外のコマンドを、スクリプトの中から打つ」形なので、持ち主がよくないと見るなら、権限の表に `uv run --frozen --project agent/sl_mcp python *` を足すか、この仮決めを戻す（報告の9）
- 戻すときに直す所：`run_numbers.py` の先頭の try/except、README の回し方。上に立つ作業：W1・W2（毎晩の見張りで回す形）

## R1-3 許す幅は、件数と金額は 0、率は 0.0005

- 日付：2026-11-13
- 決めたこと：決めごと6（正解と一番近い罠の値の差より小さい幅）から、件数・金額・行数は 0、B3 と D1 の率は 0.0005（パーセントで小数第1位、D1 の T2S の値は小数第3位の 0.455）。B3・D1 の期待値を変えたあとも、幅は変えていない
- ほかの案：(1) すべて 0（6桁でぴったり）。率は丸めの違いで外れうる。(2) 罠ごとに問の幅を細かく計算する。1回目の13問では、どの罠とも 0.0005 より離れているので、結果が変わらない
- 選んだ理由：questions.md の B3 の採点の注意（13.4% まで合えば○）をそのまま写せる。罠との差（B3 は 13.55% と 0.13 ポイント、D1 は 0.4576 と 0.0026、新しい B3 は決定メモの 30.0% と 0.5 ポイント）より小さい
- 止まる類ではないと判断した理由：試験の作り方。正解の値そのものは変えていない
- 戻すときに直す所：`bank.json` の `tolerance`

## R1-6 DuckDB が文字列で返す整数（HUGEINT）は数として比べる

- 日付：2026-11-13
- 決めたこと：(b) の比べ方で、期待が数のとき、返事が数字だけの文字列（`-?\d+(\.\d+)?`）なら数にしてから比べる
- ほかの案：SQL の側で `::bigint` に型を変える。answer_queries.sql から数え方を変えずに写す約束から外れる（型の変更でも、写して変えた所が増える）
- 選んだ理由：1回目の最初の実行で、B5・C1・C2・C3・D5 の (b) が、値は同じなのに外れた。`typeof(sum(revenue_amount))` が `HUGEINT` で、`duckdb -json` は HUGEINT を文字列で返す（`"87395105"`）。直したのは自分の比べ方の誤り
- 止まる類ではないと判断した理由：試験の道具の直し。期待値も SQL も変えていない
- 戻すときに直す所：`run_numbers.py` の `same()`
