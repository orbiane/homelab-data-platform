# M4 の報告：同じ日付の snapshot が2つある組を数える（数えるだけで、直さない）

要約：重なりのある組は **0 組／調べた 100 組（183 行）**。mart と raw の両方で同じだった。staging のビューは `run_sql` で開けなかったので、mart で代わりに数えた（仮決め 1 件）。試験の期待値を変えたのは 0 件。

## 1. 何をしたか

- `stg_revenue_monthly` の `row_number()`（並べ方は `snapshot_date desc` だけ）で選ぶ行が決まらない組、つまり同じ `account_id × revenue_month` の中に同じ `snapshot_date` が2行以上ある組を数えた
- 数え方は3つ。mart の `fct_revenue` に `run_sql` で2通り（distinct の数の差、`having count(*) > 1`）と、raw の CSV にシェルで1通り。どれも 0 組で、分母は 100 組
- 書いたものは `docs/analysis/stage3/snapshot_ties.md`。何も直していない

## 2. 終わりの条件ごとの合否

**条件1：数えた件数が、調べた組の総数と一緒に出ている → 合格**

mart（`run_sql`）：

```
select count(*) as total_rows, count(distinct (account_id, revenue_month)) as total_groups,
       count(distinct (account_id, revenue_month, snapshot_date)) as distinct_triples, ...
from main_mart.fct_revenue
→ {"total_rows":183,"total_groups":100,"distinct_triples":183,"latest_rows":"100"}

select count(*) as tied_groups from (select account_id, revenue_month from main_mart.fct_revenue
  group by account_id, revenue_month having count(*) > count(distinct snapshot_date)) t
→ {"tied_groups":0}

... group by account_id, revenue_month, snapshot_date having count(*) > 1
→ {"kind":"empty", "rows":[]}
```

raw（シェル）：

```
$ wc -l data_generation/output/revenue_monthly.csv
     184          （見出し 1 行 + 183 行）
$ cut -d, -f1-3 data_generation/output/revenue_monthly.csv | sort | uniq -d | wc -l
       0
$ cut -d, -f1-2 data_generation/output/revenue_monthly.csv | sort -u | wc -l
     101          （見出しを引いて 100 組）
```

数え方は互いに別の道で、行の数（183）も組の数（100）も一致した。

## 3. 予定と実際

- 指示書は「staging と raw の両方を `run_sql` で数える」だった。実際は次のとおり
  - staging：`main_staging.stg_revenue_monthly` はビューで、中で CSV を読む。`run_sql` はファイル操作を止めた設定なのでエラーになった（6を見る）。代わりに staging の写しの `main_mart.fct_revenue`（テーブル。staging の列を選ぶだけで、where も distinct も無い）を `run_sql` で数えた
  - raw：DB の中に無く、`run_sql` では読めない。リポジトリの中の CSV を、シェルの `cut | sort | uniq` で読むだけで数えた
  - この2つは仮決め M4-1 にした
- 仮決めの記録 `docs/agent/provisional/M4.md` は、loop.md の4の決まりで増えたファイル。終わりの条件の「snapshot_ties.md と報告だけ」からは外れる（M1 で報告を数えなかったのと同じ扱い）

## 4. 詰まった所

- staging のビューへの `run_sql` が1回エラーになった。同じ所に言い直しはせず、mart のテーブルに切り替えて1回で通った

- staging のビューそのものは数えていない。mart は前回の `dbt build` のときの写し。今回は sha256 の照合が OK で、行の数も CSV と同じだった
