## 9. まだ怪しい点

- 写した文の読み方。「個人の私的利用を超えて」使うことと、「改変して、転用、複製等をすること」の両方が、書面の承諾なしには禁止と読める。生の行を入れず集計だけを公開リポジトリに入れる使い方（指示書の 1-2 の形）も、「改変して転用」に入ると読める。入らないと読む余地もありそうだが、止まる類かどうか迷うときは止まる側にした
- 「データ」の扱い。需要の実績の数字そのものに著作権があるかは、この文からは分からない。ただ、文は「情報」全体を対象にしており、条件として読むには十分だと考えた（法的な判断はしていない）
- P3 の前に確かめが要ること（止まった理由とは別。P1 を続けるときに効く）：ループの権限の表（`.claude/loop-settings.json`）の deny `Edit(**/_metrics.yml)`・`Edit(**/_semantic_models.yml)` は、どのディレクトリにも当たるので、`power/dbt_project/models/` の下の同じ名前のファイルにも当たる見込み。一方、ADR-007 の道具の入口（`.claude/hooks/adr007_guard.py` の `kind_of`）とコミットの入口（`.githooks/definition_guard.sh`）は、`dbt_project/models/` で**始まる**パスだけを定義として見ていて、`power/` は見ていない（どちらもコードを読んで確かめた。動かしてはいない）。なので、指示書の項目9の「関所は `dbt_project/models/` だけを見る」は2つの関所については正しいが、権限の表は `power/` の定義の Edit も断る。P3 は、定義のファイルの Edit で断られる見込みが高い。名前を変えて避けるのは守りの話なので、持ち主が決めること

## 10. 持ち主に決めてほしいこと

**東京電力の過去の需要実績を、この公開リポジトリの題材に使ってよいか。使うならどの形でか。**

上に写した `/legal/` の「著作権について」は、事前の書面の承諾なしに、個人の私的利用を超えて使うことや、改変して転用・複製することを禁じていると読める。指示書の形（生の行は入れず、コード・一覧・集計を公開リポジトリに入れる）も、これに当たると読める。

- A：持ち主が、東京電力（`/legal/` の「その他の転載・引用については、こちらにご連絡ください」の連絡先）に、書面の承諾を求める。承諾が取れたら、その範囲で P1 をやり直す。時間はかかるが、一番はっきりする
- B：取り込みと手元の分析は私的な利用として進め、公開リポジトリには、コードと取り込みの一覧（URL・sha256・大きさ・行の数）だけを入れる。集計の値も入れない。P3 の `power/docs/baseline.md`（集計の値を書く）と、P4 の回帰の試験の期待値の置き方を変える必要がある。それでも「私的利用を超えて」に当たらないかは、持ち主の判断になる
- C：利用の条件がはっきり書かれた、別の出どころに替える。どこにするかは、持ち主か、持ち主が頼んだセッションが指示書を書き直して決める（この回では、ほかの出どころのライセンスを調べていない）

推す案：**C**（次点 A）。この題材でいちばん見たいのは「配る側が過去の値を黙って直す」腐敗で、それはでんき予報の注記（上に写した1つ目の※）に書いてあるとおり、この出どころの強みでもある。ただ、公開リポジトリに結果を載せることがこの作業の前提なので、条件が「書面の承諾なしには禁止」と読める出どころの上に P1〜P5 を積むと、あとで全部を下ろすことになりうる。B は、P3・P4 で集計の値を公開できないので、回帰の試験と振り返りの材料が細る。A が取れるなら A がいちばんよい。
