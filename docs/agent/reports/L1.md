## 3. 予定と実際

1. 権限モード：指示書は Manual だが、このセッションは auto。L0 と同じく、`.claude/` の変更・`claude -p` の試しは、その都度聞いた。途中で持ち主が「API は積極的に使ってよい、試しの PR などは承認する、早く」と言ったので、その後の push・試しの PR・コメントは聞かずに進めた
2. 続きの回でブランチに乗せるのは台本（`run.py`）。ループの表（`loop-settings.json`）は変えていない
3. `owner/L1-order`（PR #3）が L1 の「済み」に数えられる件は、直さず記録だけ（下の 9）
4. レビューの試しは、試しの PR #16 だけ（`run.py --review-pr` を足した）。#11〜#13 にはコメントを付けていない
5. `.claude/review-settings.json` は、持ち主に中身を見せてから作った。1回目の試しで、予定・worktree・下請けのエージェントなど、機械の外に何かを作れる道具が残っていると分かり、持ち主の承認で deny に13個足した
6. 試し3-2 の「決め: 試し」は、持ち主の許しで、このセッション（Claude）が `gh pr comment` で書いた。本番では持ち主だけが書く（K9）

## 9. まだ怪しい点

- **据え付け直すまで、定時の回はレビューしない。** launchd が起こすのは `~/homelab-loop/bin` の写しなので、マージのあと `python3 agent/loop/install.py copy --ref origin/main` が要る。写し直した最初の定時の回で、#11〜#13（と、その時に開いている PR）に初めてレビューが付く（1つ 0.2 ドル前後）
- **PR #8（ループのモデルを Fable にする）と `run.py` がぶつかる。** #8 は `MODEL` の行と `start`・`end` の記録の行を変えている。L1 も同じ記録の行に `cont`・`pr` を足した。後からマージする方で直しが要る
- ループの表（`.claude/loop-settings.json`）にも、レビュー役で見つけたのと同じ道具（予定・worktree・下請けのエージェントなど）が残っている見込み。確かめていない（L1 の範囲の外）
- `owner/L1-order`（PR #3、マージ済み）が、`pick.py` の規則で L1 の「済み」に数えられる。`owner/L1` がマージされれば実害は無いが、`owner/L1` が閉じられても L1 は済みのまま（Z1 の ALL に効く）。持ち主の決めで直していない
- 続きの回を本当に回したことは無い（`--dry-run` で選ぶところまで）。`checkout_branch` と `sync_pr_body`（`gh pr edit`）は、本番で初めて動く
- `sync_pr_body` は、台本が PR の本文を書き換える。止まる類（GitHub の設定・権限の表）には当たらないと判断したが、迷う所
- `reviews.jsonl` は機械の上にあり、ループのスクリプト（ADR-008 の K2）からは書き換えられる。書き換えれば、偽のレビューを「台本のもの」に数えさせられる
- レビュー役の init の道具の一覧に Glob・Grep が無い（この版では Bash の中にあるらしい）。指示書の「Read・Glob・Grep」とは見え方が違う
- ユーザーの設定の出力の形がレビュー役にも効く。試し deny2 の返事には説明の枠が入った。PR #16 のコメントには入っていない（`grep -c Insight` が 0）が、入ることはありうる
- 試しの PR #16 と `auto/L1-trial` は、この PR を出したあと閉じて消す（持ち主の承認済み）。PR #16 には、私が書いた「決め: 試し」と偽の「レビュー:」のコメントが残る
