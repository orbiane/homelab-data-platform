# 報告：L0 自律ループを据え付ける

日付：2026-11-09〜10。ブランチ：`owner/L0-loop-setup`（PR #4）。持ち主が見ているセッションで進めた（ただし権限モードは auto で、指示書の Manual ではなかった。下の「食い違った点」）。

## 何をしたか

- ループ専用の権限の表（`.claude/loop-settings.json`）と、push・gh・dbt を絞るループの関所（`.claude/hooks/loop_guard.py`）を作り、試しの表で確かめた
- GitHub の ruleset で `main` を守った。ループ専用の作業場所（`~/homelab-loop/wt`）、起動の台本（`agent/loop/`）、LaunchAgent を据え付けた
- ループと同じ起動で権限の試しを24本回し、最初の1件（M2）を手で回して PR #5 を出させた。LaunchAgent を読み込んだ

## 食い違った点（指示書に無い判断）

持ち主がその場で決めたこと：

1. 権限モード：指示書は Manual だが、このセッションは auto で動いていた。承認が要る操作（push、`gh api`、ブランチの削除、LaunchAgent）は、その都度、持ち主にはっきり聞いた
2. ループの起動は `--setting-sources user`（持ち主の選択）。ユーザーの設定（`~/secure` の deny、`ask-local` の allow、`DBT_PROFILES_DIR`、出力の形）もループに効く
3. 起動の台本と守りのファイル（ループの表、ループの関所、`pick.py`、`prompt.md`）を、作業場所の外の `~/homelab-loop/bin` に写して起こす（持ち主の選択）。マージ前の M2 も、作業は `origin/main` から、守りは L0 の版で回せた
4. ループの表の hook に `"onFailure": "block"` を足した（指示書は「そのまま入れる」。持ち主の選択）
5. L0 の PR は、試しと M2 が済んだあと Claude がマージしてよい（持ち主の許可。記録上、L0 のマージは人ではなく Claude がした形になる。ADR-008 の決定3と CLAUDE.md の守ること4の例外）
6. 始めない時間帯を、指示書の JST 02:30〜03:30 から 01:20〜03:30 に広げた（起動が毎時23分・上限90分なので、01:23 と 02:23 の回が 03:00 の dbt build に重なりうる。別のセッションのレビューで見つかり、持ち主が決めた）
7. 試し x5・x6 は、頼む文に守る場所の名前が入るので、私のセッションの ADR-007 の関所（R5）に止められた。名前を隠して通すのは H2 と同じ形なので一度は回さず、持ち主の端末で打つよう頼んだが、持ち主が「Claude が打ってほしい」と求めたので、文をリポジトリの外のファイルに置いて `trial.py --action-file` で渡した。関所は変えていない

私が仮決めしたこと（中身は `docs/agent/provisional/L0.md`、11件）：L0-1 据え付けの台本、L0-2 ループの関所の範囲を広げた、L0-3 ループの表の deny を足した、L0-4 マージ＋開いた PR は済み、L0-5 symlink を info/exclude で見えなくする、L0-6 定義の Edit を deny、L0-7 `--permission-prompts none`、L0-8 台本が作業場所を戻し ID を選ぶ・`--only` は依存を見ない、L0-9 試しの台本、L0-10 `--add-dir`、L0-11 前置きの書き方の決まり。

loop.md と食い違う作りにしたので、`docs/agent/loop.md` の 1（台本が作業場所を戻す、照合のあと戻る）・2（選ぶのは `pick.py`）・6（`--body-file`、push の形、1回に1つのコマンド）を同じ PR で直した。

## まだ怪しい点

- ループの中で ADR-007 の R2（決定メモのパスの無い定義の Edit を止める）が効くかは確かめていない。試し x5 は、それより前に権限の表の deny で止まった
- launchd から起こした `claude -p` のログイン（止まる条件2）は、まだ確かめていない。マージ後に最初に Claude を起こす回の記録（`runs.jsonl` の `end` と stream-json の init）で確かめる
- GitHub が ruleset に勝手に足した `require_extra_approval_for_unattributed_changes: true` の意味が分からない（説明が見つからなかった）。マージが止まらないかで確かめる
- ユーザーの設定の出力の形（Explanatory）がループにも効き、返事と報告に説明の枠が入る。権限には関係しないが、費用と報告の文に効く
- 私のセッションの ADR-007 の関所は、読むだけのコマンドも名前で止める（`git config` で hooksPath を読む、`~/.claude/settings.json` を読む、コミットメッセージの "apply" と `git add .claude/hooks/...` が同じ行にある）。別のセッションは、`git log -n 2` や `stream-json` のようなハイフン付きの語が `commit -n` と読まれる誤検知に当たった
- ADR-007 の関所は `.claude/loop-settings.json` と `agent/loop/` を守らない。ループの側は deny と protected paths で守っているが、持ち主のセッションの側では守られていない
- PR #3（L1）との合わせ目（別のセッションが見つけた）：ブランチ名 `owner/L1-order` は `pick.py` の規則で L1 の「済み」に数えられ、Z1 の ALL に効く。PR #3 は「本文の1行目が『途中』なら続きを選ぶ」が、L0 は本文を報告のファイルにした（1行目は見出し）。どちらも L1 で合わせる
- 守りの写しは、マージのあと `origin/main` から写し直す（README の据え付けの3）。写し直すまでは `runs.jsonl` の `guard_drift` に出る
- 起動の台本は `uv run python` を許すので、スクリプトの中では権限の表も関所も効かない（ADR-008 の K2）。守りの写しも、K2 からは書き換えられる
