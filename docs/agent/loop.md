# 自律ループの手順（ADR-008）

このファイルは、持ち主が承認した、自律ループの毎回の手順。定時に起動された Claude Code（人が見ていない、承認の画面が出ないセッション）は、この手順だけに従う。

- 起動するのは、持ち主の機械の定時の仕組み（`agent/loop/` の起動の台本。L0 で据え付ける）
- 承認の画面は出ない（`dontAsk`）。権限の表（`.claude/loop-settings.json`）に書いたことだけができる。それ以外は自動で断られる。断られたら、別の書き方で通そうとしない
- ADR-007 の関所（定義と決定メモと守りそのもの）は、ループでもそのまま効く。定義・決定メモ・守りそのものは、ループでは変えられない（承認が要るので、断られる）

## 1回の起動でやること

### 1. 始める前に

1. 作業場所（ループ専用の git worktree）で `git fetch origin` し、`main` の最新から始める。作業場所に、前の回の消えていない変更があれば、何もせずに止まる（報告だけ）
2. データの版を照合する（`cd data_generation/output && shasum -a 256 -c ../output.sha256`）。合わなければ止まる
3. JST 02:50〜03:15 は毎晩の `dbt build` の時間。その時間にかかる作業は始めない
4. `CLAUDE.md`、`NEXT.md`、この文書を読む

### 2. 1件を選ぶ

- `NEXT.md` の表を上から見て、状態が `ready` で、依存がすべて `done` の最初の行を選ぶ
- その ID の作業ブランチ `auto/<ID>` に、開いている PR か閉じた PR があれば、その行は飛ばす（閉じた PR は、持ち主が断ったという意味。やり直さない）
- 開いているループの PR が3つ以上あれば、何も始めずに終わる（持ち主のマージを待つ）
- 選べる行が無ければ、何もせずに終わる

### 3. 進める

- `main` から `auto/<ID>` を作り、行の指示書（無ければ `NEXT.md` の「小さな作業」）に従う
- 指示書の「終わりの条件」をすべて満たすまで直しては確かめる。CLAUDE.md の「作業の進め方」をそのまま守る
- 区切りごとに `auto/<ID>` に push する（持ち主とチャットは、git に届いたものしか見えない）
- 1回の起動の上限：90分。上限が来たら、そこまでを push し、報告に「途中」と書いて終わる。次の回は、その PR を飛ばすので、続きは持ち主かチャットが別の行として起こす

### 4. 止まる

次のどれかに当たったら、その場で止まり、報告だけを書いて PR を出す。`NEXT.md` のその行の状態は `blocked` にする（その PR の中で）。

- 指示書に無い設計判断が要る（推す案があれば理由を添えて書き、決めない）
- 権限の表に断られた。関所（ADR-007）に止められた
- 指示書の止まる条件に当たった
- 同じ条件で2回直しても通らない
- データの版の照合が合わない

### 5. 報告と PR

- 報告は `docs/agent/reports/<ID>.md`（平易な日本語、短く）：何をしたか／確かめたこと（実行したコマンドと出力）／食い違った点（指示書に無い判断をした所と理由）／まだ怪しい点／持ち主に決めてほしいこと
- 同じ PR で、`NEXT.md` のその行の「状態」を `done`（止まったときは `blocked`）に、「PR」の欄を PR の番号にする。ほかの行と、表の外の文は変えない。マージされたときに `main` で `done` になる。閉じられたら `main` は変わらない（閉じた PR がある行は、2 の規則で飛ばす）
- PR が開いている間の行は `in-pr` と読む（表の文字ではなく、GitHub の PR の状態で決める）
- PR の本文は、報告の要約と、終わりの条件ごとの合否。最後に、持ち主に決めてほしいことを1つにまとめて書く
- `gh pr create` で PR を作る。番号が出たら、`NEXT.md` の PR の欄に書いて、同じブランチに push する。**マージはしない**

## やらないこと

- マージ。`main` への push。作業ブランチ `auto/<ID>` 以外への push
- 定義（ADR-007 の定義のファイル）、決定メモ（`docs/business/`）、守りそのもの（`.claude/`、`.githooks/`）の書き換え。権限の表の書き換え
- `data_generation/` の generator の再実行、`warehouse.duckdb` への書き込み、`dbt build`
- ツールのバージョンを上げること
- 1回の起動で2件以上を進めること
- `NEXT.md` に、新しい行を足すこと（見つけたことは報告の「持ち主に決めてほしいこと」に書く）

## 持ち主とチャットの側

- 持ち主：PR を見てマージする（＝承認）。断るときは PR を閉じる。決めごと（状態 `owner` の行）は、チャットに一言で伝える
- チャット（claude.ai の会話）：PR を clone して確かめ、持ち主に「マージしてよいか」を短く伝える。持ち主の決めごとを `NEXT.md` と ADR に書き、新しい行と指示書を足す
