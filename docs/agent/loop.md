# 自律ループの手順（ADR-008・ADR-009）

このファイルは、持ち主が承認した、自律ループの毎回の手順。定時に起動された Claude Code（人が見ていない、承認の画面が出ないセッション）は、この手順だけに従う。

- 起動するのは、持ち主の機械の定時の仕組み（`agent/loop/` の起動の台本。L0 で据え付ける）
- 承認の画面は出ない（`dontAsk`）。権限の表（`.claude/loop-settings.json`）に書いたことだけができる。それ以外は自動で断られる。断られたら、別の書き方で通そうとしない
- ADR-007 の関所（定義と決定メモと守りそのもの）は、ループでもそのまま効く
- 今は**ビルドの段**（ADR-009）。目的は、`NEXT.md` の作業を実装まで進め、あとで評価できる記録を残すこと

## 1回の起動でやること

### 1. 始める前に

1. 作業場所（ループ専用の git worktree）は、起動の台本（`agent/loop/run.py`）が、消えていない変更が無いことを確かめてから `git fetch` し、`origin/main` の最新に戻してある（detached HEAD）。前の回の変更が残っていれば、台本が Claude を起こさずに止まる。`git status` と `git log -1` で、そうなっていることだけを確かめる
2. データの版を照合する（`cd data_generation/output && shasum -a 256 -c ../output.sha256`）。合わなければ止まる
3. JST 02:50〜03:15 は毎晩の `dbt build` の時間。その時間にかかる作業は始めない
4. `CLAUDE.md`、`NEXT.md`、この文書、ADR-009 を読む

### 2. 1件を選ぶ

**選ぶのは起動の台本（`agent/loop/pick.py`）で、モデルは選び直さない。** 前置きに書かれた ID を進める。持ち主が手で `run.py --only <ID>` を打ったときは、依存が済んでいなくても、その ID を進める（L0 で決めた）。下は、`pick.py` が使う規則。

作業の状態は、`NEXT.md` の表の「種類」と、GitHub の PR で決まる（ADR-009 の決定6）。

- 済み：その ID の作業ブランチ（`auto/<ID>`、`owner/<ID>`、またはその後ろに `-` で始まる名前を付けたもの）の PR がマージされている
- 進行中：そのブランチの PR が開いている
- 断られた：そのブランチの PR が閉じられていて、マージされていない。やり直さない

選び方：

- `NEXT.md` の表を上から見て、種類が `loop` で、まだ PR が無く、依存がすべて済みの最初の行を選ぶ
- 種類が `attended`（持ち主の見ているセッションでやる）と `owner`（持ち主が決める）の行は選ばない
- 開いているループの PR が3つ以上あれば、何も始めずに終わる（持ち主のマージを待つ）
- 選べる行が無ければ、何もせずに終わる

### 3. 進める

- `main` から `auto/<ID>` を作り、行の指示書（無ければ `NEXT.md` の「小さな作業」）に従う
- 指示書の「終わりの条件」をすべて満たすまで直しては確かめる。CLAUDE.md の「作業の進め方」をそのまま守る
- 区切りごとに `auto/<ID>` に push する（持ち主とチャットは、git に届いたものしか見えない）
- 1回の起動の上限：90分。上限が来たら、そこまでを push し、報告に「途中」と書いて PR を出して終わる。続きは、チャットが別の行として起こす

### 4. 決めごとが要ったとき（ADR-009）

指示書に無い設計判断が要ったら、まず止まる類かどうかを見る。

**止まる類**（決めずに止まる。5 へ）：

- 定義（ADR-007 の定義のファイル）と、決定メモ（`docs/business/`）
- 仕込んだ汚れの扱い（CLAUDE.md の守ること1）と、既存の `dbt_project/` の staging・mart の数え方
- 基準データの作り直し（generator を `data_generation/output/` に向けて回すこと、`dbt_project/warehouse.duckdb` への書き込み）
- 守りそのもの（`.claude/`、`.githooks/`）、権限の表、GitHub の設定、定時の仕組み
- 費用の上限を超えること、元に戻せないこと
- 止まる類かどうか迷ったとき

**それ以外**（仮決めして進める）：推す案で決め、`docs/agent/provisional/<ID>.md` に記録して続ける。形は `docs/agent/provisional/README.md`。ほかの案を少なくとも1つ書く。

### 5. 止まる

次のどれかに当たったら、その場で止まり、報告だけを書いて PR を出す。

- 止まる類の決めごとが要る（推す案があれば理由を添えて書き、決めない）
- 権限の表に断られた。関所（ADR-007）に止められた
- 指示書の止まる条件に当たった
- 同じ条件で2回直しても通らない
- データの版の照合が合わない

### 6. 報告と PR

- 報告は `docs/agent/reports/<ID>.md`。形は下の「報告の形」
- 作業の PR では、`NEXT.md` と `docs/decisions/README.md` を書き換えない（ADR-009 の決定6。マージのあとにチャットが直す）
- PR の本文：報告の要約、終わりの条件ごとの合否、仮決めの件数、試験の期待値を変えた件数。止まったときは、持ち主に決めてほしいことを1つにまとめて書く
- `gh pr create --base main --head auto/<ID> --title "<ID>: <一言>" --body-file docs/agent/reports/<ID>.md` で PR を作る（本文をコマンドの中に書くと、複数行や記号でコマンドとして読み切れず、権限の表に断られる）。**マージはしない**
- push は `git push -u origin auto/<ID>` の形だけ（ループの関所がほかの形を止める）。Bash は1回に1つのコマンドで打つ

## 報告の形（ADR-009 の決定5）

分析の段で、ここが材料になる。平易な日本語で、短く。無かった項目は「無し」と書く（空けない）。

1. 何をしたか（3行まで）
2. 終わりの条件ごとの合否：実行したコマンドと出力
3. 予定と実際：指示書のとおりに行かなかった所と、その理由
4. 詰まった所：何が失敗したか、何回試したか、何で直ったか（直らなかったら、何が足りないか）
5. 選んだ設計：仮決めの番号と一言（中身は `docs/agent/provisional/<ID>.md`）
6. 止められた操作：権限の表に断られた・関所に止められた呼び出し（道具の名前、対象、理由の文）
7. 試験の正解を変えたか：変えた問、前の値、新しい値、理由、コミット
8. 費用と時間：分かる範囲（ループの記録の場所を添える）
9. まだ怪しい点
10. 持ち主に決めてほしいこと（止まったときだけ。1つにまとめる）

## 試験の期待値を変えるとき（ADR-009 の決定4）

- 回帰の試験の期待値は、変えてよい
- 期待値の変更だけのコミットに分ける。コミットメッセージは `expected:` で始める
- bank の出どころの欄に、作業 ID・日付・前の値・変えた理由・2通りで出した値を書く
- 報告の7に書く

## やらないこと

- マージ。`main` への push。作業ブランチ `auto/<ID>` 以外への push
- 止まる類の変更（上の4）
- 指示書が明示して許した場合を除く、`data_generation/` の generator の実行、`dbt_project/warehouse.duckdb` への書き込み、`dbt_project/` での `dbt build`
- ツールのバージョンを上げること
- 1回の起動で2件以上を進めること
- `NEXT.md` に新しい行を足すこと（見つけたことは報告の9か10に書く）

## 持ち主とチャットの側

- 持ち主：PR を見てマージする（＝承認、仮決めの承認も含む）。断るときは PR を閉じる。`attended` の行は、持ち主が見ているセッションに1行を送って進める
- チャット（claude.ai の会話）：PR を clone して確かめ、持ち主に「マージしてよいか」を短く伝える。マージのあと、`NEXT.md` の「済んだ作業」と `docs/decisions/README.md` の一覧を直す。新しい行と指示書を足す
