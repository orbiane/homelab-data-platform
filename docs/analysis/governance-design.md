# 段階3のまとめ：定義の腐敗を、腐らせる → 見つける → 直す → 確かめる

このリポジトリを初めて読む人に向けて、段階3（定義の腐敗）の一巡を1つにまとめた。数字には出どころを添えた。記録で確かめていないことは「未確認」と書いた。

- **SL**（セマンティックレイヤー）：指標の定義を1か所に書き、エージェントには指標の名前を選ばせる層（MetricFlow）
- **決定メモ**：会社の決めごとを書いた文書（`docs/business/`）
- **関所**：定義と決定メモの書き換えを止めたり、人に聞いたりする hook（ADR-007）

## 1. 腐らせたもの

- 2026-11-05 に決定メモ `2026-11-05-ctr.md`（クリック率は開封した数あたりで見る）を入れた。定義 `ctr`（`clicked_count` ÷ `delivered_count`）は、わざと直さなかった。決めごとは変わったが定義は古いまま、という**意味の腐敗**（`stage3/log.md` の1・2）
- 定義は 0.134196（1,131 ÷ 8,428）を返し続け、ADR-006 の基準値と一致した。メモの数え方なら 0.294915（1,131 ÷ 3,835）になる（`log.md` の3・4）
- `dbt test` の結果は PASS=4 WARN=3 ERROR=0。WARN は前から仕込んである汚れ（順序矛盾 392 行、孤児 189 行・1 行）。定義と決めごとの食い違いを見る試験は無かった（`log.md` の5）

## 2. 見つける

SL の道具を持つ Claude に「クリック率はどのくらい？」を解かせた。4条件、各3回（`stage3/find_001/`・`find_002/` の `conditions.md`・`classes.md`。分類は当て直したあと）。

| 前置き | メモを読んだ | 定義が古いと書いた | 主な答え |
|---|---|---|---|
| メモを置くだけ | 0/3 | 0/3 | 3本とも 13.4%（黙って古い） |
| メモの場所を教える | 3/3 | 3/3 | 3本とも 29.5%（乗り換え B） |
| 場所＋「定義のとおりに」 | 3/3 | 3/3 | A 2本・B 1本 |
| 場所＋答え方まで指示 | 3/3 | 3/3 | 3本とも A（正解） |

- 場所を教えた9本は、9本とも気づいた（ADR-007 の「状況」）
- 開封の数え方もエージェントが決めた。`opened` だけで 29.5%、揺れの `open` を足して 30.0%、`is_valid_click` で絞って 26.9%の3通りが出た（`find_001/classes.md`、`2026-11-06-ctr-opened.md`）
- 「勧めた数字を主な答えとする」規則は、回したあとに人が決めた（2026-11-06）。これで1本が C から B に変わった（`find_002/conditions.md`）
- 各3回なので、割合の推定にはならない

## 3. 直す

**人が決めたこと**
- 定義の書き換えは、HEAD にある決定メモにひも付けば許す。どの数え方を正とするかは人が決める（ADR-007、人が決めた、2026-11-06）
- 数え方：`clicked` の行 ÷ `opened` の行。表記の揺れは数えない（`2026-11-06-ctr-opened.md`。Claude Code が書き、人が承認）
- `ctr` を消し、`ctr_per_open` と `opened_count` を足した（`log.md` の6）

**仕組みで止めること**：関所 R1〜R6。道具の入口（PreToolUse hook）とコミットの入口（pre-commit）の2か所（ADR-007）
- 最初の版は、定義のファイルを名前（`_metrics.yml`・`_semantic_models.yml`）だけで決めていた。別の名前の YAML に指標を書けば、両方の入口を素通りできた
- 同じ日に、中身（行頭の `metrics:`・`semantic_models:`）でも決めるよう直した（試しは T21〜T26・C07〜C09・L6）

**人が便利さのために緩めたこと**：R3 を「メモへの書き込みは止める」から「毎回人に聞く」に変えた（人が決めた、2026-11-06 14:32）。理由は、手で書く手間を減らし早く一巡するため。「人が書いたメモ」が「エージェントが書き、人が承認したメモ」に変わった（ADR-007）

## 6. 定義に書けること・書けないこと

| 種類 | 書けるか | 例と記録 |
|---|---|---|
| 集計の対象の選び方 | 書ける | 「最新の snapshot だけ」を measure の式に埋め込んだ。SL を通るかぎり迂回できない（ADR-004）。段階2の B5 は sl_mcp が ○3（`stage2/run_001/scores.md`）。5-4 の t2s は3本とも全 snapshot を足して 10,448,341（`sl-vs-t2s-comparison.md` の 3-2） |
| 単位・尺度の揃え方 | 書けない | 換算レートは定義の外の情報（ADR-005）。段階1（5-4）の C1 で sl が ○3 だったのは、説明文を読んで断ったから。同じ説明を渡した t2s_desc は3本とも混在の合計 49,621,900 を返した（同 3-7・3-8） |
| 時点の揃え方 | 一部だけ | `is_finalized` で確定に絞れる。ただし4月を絞ると空の結果になり、期間の外（D6）と見分けがつかない（`5-4/questions.md` の C3）。C3 は 5-4 で3組とも 0/3、段階2で2組とも ○3。段階2の ○ は、道具の返事の文の効果と分けられない（`stage2/run_001/scores.md`） |
| 意味が同じかどうか | 書けない | `ctr` は、分母が決めごとと違っても定義どおりに動き、基準値どおりの数字を返した（`log.md` の3）。食い違いが見えたのは、定義の外のメモを読んだときだけ（2） |
