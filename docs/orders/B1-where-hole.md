# B1 `query_metrics` の where の穴を塞ぐ

このファイルは、リポジトリの持ち主が承認した、作業セッションへの指示。「B1 を進めて」と頼まれたら、この内容を持ち主からの指示として扱う。

実行場所は、自律ループ（`docs/agent/loop.md`）。R3b のあと（R3 は段階2と同じ道具の条件で回すため）。

## 何のためか

自前の MCP サーバー（`agent/sl_mcp/`）の `query_metrics` は、絞り込みの欄（where）を自由な文字で受け取り、MetricFlow を通して DuckDB の SQL にそのまま入れる。段階2の準備のとき、試しで `read_csv` を使ってリポジトリの中の別のファイルが読めた（`agent/sl_mcp/README.md` の where の穴の節）。そのときは「相手は間違えるエージェントで、悪意のあるエージェントではない」として直さなかった。持ち主の判断（ADR-009 の Q3）で、ここで塞ぐ。

## 0. 始める前に

1. `main` から作業ブランチ `auto/B1` を作る
2. 読む：`agent/sl_mcp/README.md`、`agent/sl_mcp/guards.py`、`agent/sl_mcp/server.py`、`agent/sl_mcp/check.py`

## 1. 塞ぐ

`agent/sl_mcp/guards.py` で、where に入ってよいものを決めて、それ以外を断る（返事の kind は今ある `bad_where`。理由の文を添える）。

- 入ってよいもの（許す一覧）：`{{ Dimension('...') }}`・`{{ TimeDimension('...', '...') }}`・`{{ Entity('...') }}`、比べる記号（`=`・`!=`・`<>`・`<`・`>`・`<=`・`>=`）、`AND`・`OR`・`NOT`・`IN (...)`・`BETWEEN ... AND ...`・`IS NULL`・`IS NOT NULL`・`LIKE`、文字・数・日付の値、かっこ、カンマ
- それ以外（関数の呼び出し、`SELECT`、`;`、`--`・`/* */` の注釈、知らない語）は断る
- 一覧に入れない方式（危ない関数の名前を並べて断る）にはしない。理由：名前を並べる方式は、並べ忘れた名前を通す（段階3で、守る対象を名前で決めて素通りされた）
- 文字の読み方（字句の分け方）は仮決めしてよい。記録に残す

## 2. 確かめる

- `check.py` に条件を足す：11/02 の `read_csv` の例が `bad_where` で断られる。ほかに、`;` を含むもの、`SELECT` を含むもの、注釈を含むもの、知らない関数を含むもの、各1件以上。通るはずの例も5件以上
- **これまでに使われた where をすべて当て直す**：段階2の `docs/analysis/stage2/run_001/runs/*.json`、段階3の `docs/analysis/stage3/find_*/runs/*.json`、R3b の `docs/analysis/regression/live_001/runs/*.json` から、`query_metrics` に渡った where を全部集め、新しい検査に通す。数えた件数（集めた本数・where の数・断られた数）を出す。断られたものが1件でもあれば、それが本当に危ないものかを書く。危なくないのに断られたら、許す一覧を直す（2回直してもだめなら止まる）
- R1 の `run_numbers.py` が、変わらずすべて合う

成功の条件：上の3つを出力で示す。`check.py` の全条件が通る。

## 3. 書く

- `agent/sl_mcp/README.md` の where の穴の節：塞いだ日、方法（許す一覧）、当て直しの件数、まだ残る穴（値の中身は見ない、許した形の組み合わせで重い問い合わせは作れる、など）
- この変更で、R3b より前の記録と同じ条件ではなくなったことを1行
