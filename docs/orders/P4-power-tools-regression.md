# P4 新しい題材：道具と回帰の試験、改訂の検知

このファイルは、リポジトリの持ち主が承認した、作業セッションへの指示。「P4 を進めて」と頼まれたら、この内容を持ち主からの指示として扱う。

実行場所は、自律ループ（`docs/agent/loop.md`）。B1（where の穴を塞いだ）のあと。

## 何のためか

電力の題材でも、決めた数字を毎回同じ数え方で出せるようにし（SL の道具）、変更のたびに解き直して崩れていないかを見る（回帰の試験）。加えて、配る側が過去の値を黙って直したときに、どの数字が動いたかを出す。

## 0. 始める前に

1. `main` から作業ブランチ `auto/P4` を作る
2. 読む：ADR-011、`power/` の下、`agent/sl_mcp/README.md`・`server.py`・`guards.py`・`check.py`、`docs/analysis/regression/README.md`

## 1. 道具に電力の形を足す

- `agent/sl_mcp/` のサーバーが、環境変数（名前は仮決め。例：`SL_MCP_PROJECT=power`）で、電力の dbt プロジェクトを相手にできるようにする。指定が無ければ今までどおり。道具の名前・返事の kind・where の検査（B1）は同じ
- `check.py` に、電力の形の条件を足す（既存の条件はすべて通ったまま）
- MCP の登録（`.mcp.json`）とループの権限の表は変えない（P5 で持ち主がやる）。試験はサーバーを import して呼ぶ（`check.py` と同じ形）

## 2. 電力の回帰の試験

- `power/regression/`：問を5〜8個（仮決め）。例：ある日の最大需要、ある月の需要の合計、ある夏の日の平均気温。各問に、SL の道具の呼び出しと、SQL（Python の DuckDB で読むだけで開く）の2通り、期待値、出どころ（ADR-011 の節と、取り込みの一覧の版）
- 期待値は、2通りで一致した値だけ
- 回し方は `docs/analysis/regression/` と同じ形（問ごとに合う／外れる、件数、外れがあれば終了コード 1）

## 3. 改訂の検知

- P2 の取り込みを1回回し、前の版と指紋が変わったファイルがあるかを見る
- 変わったファイルがあれば、どの時刻の値が変わったかと、それで回帰の試験のどの問が動くかを出す。無ければ「この日は0件」と書く
- 作り物で確かめる：一時ディレクトリで、1つの値を変えた写しから作ったとき、試験の該当の問が外れることを示す

成功の条件：1 の `check.py` がすべて通る。2 の試験が今のデータで外れ0。3 の作り物で外れが出る。結果を `power/regression/results/<日付>.md` に。
