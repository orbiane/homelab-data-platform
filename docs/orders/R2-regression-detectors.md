# R2 回帰の試験 第2段：過去の間違いの検出器と、人の判定との突き合わせ

このファイルは、リポジトリの持ち主が承認した、作業セッションへの指示。「R2 を進めて」と頼まれたら、この内容を持ち主からの指示として扱う。

実行場所は、自律ループ（`docs/agent/loop.md`）。エージェントは回さない（記録を読むだけ）。

## 何のためか

段階2では、値は合っているのに数え方が定義と違う答え（年を見ずに月で絞った、など）を、人の目（チャット）が78本中5本見落とした。自動の採点も、答えが長くなると両方向に外れた（B4 の正しい分解を×、B3 の罠を○）。そこで、過去の間違いを、**答えの数字ではなく、道具の呼び出し（`query_metrics` の引数、`run_sql` の SQL）から見つける検出器**にする。

検出器が当てになるかは、人が確定した判定と突き合わせて測る。物差しは、人の判定（`docs/analysis/stage2/run_001/final_scores.tsv`、持ち主が確定）と、5-4 の判定（`docs/analysis/5-4/run_002/scores.md`）。検出器を作ったのも測るのも Claude なので、ここだけは人の判定を独立した物差しにする。

## 0. 始める前に

1. `main` から作業ブランチ `auto/R2` を作る
2. `docs/analysis/regression/README.md`（R1）、`docs/analysis/5-4/questions.md` の「原因の札」、`docs/analysis/stage2/run_001/scores.md`（軸1 の規則A〜C）、`final_scores.tsv`、5-4 の `scores.md` の「印」の節を読む

## 1. 検出器を書く（記録の中身を見る前に）

`docs/analysis/regression/detectors.py` に、知られた間違いごとに1つの関数。入力は1本の記録（`runs/*.json` の `calls` と `final_answer`）、出力は「当たった／当たらない／判定できない」と根拠（どの呼び出しのどこか）。

- 最初の版は、間違いの説明（questions.md の原因の札、`final_scores.tsv` の tags・mark・note の言葉、5-4 の印の説明）だけから書く。**記録の `calls` の中身を見る前にコミットする**（コミット1）。回した後に決めた規則にしないため
- 少なくとも次を入れる：年を見ずに月で絞る（`month(...) = 2` だけで年が無い）／品質フラグ（`is_valid_*`）で行を除く／未確定の月を外す（`is_finalized` で絞って比べる）／孤児の行を内部結合で落とす／snapshot を全部足す／通貨を混ぜて足す／確定値にだけある行を差に入れる（D5）／空の結果を 0 と読む（答えの文から）
- 各検出器に、どの問に当てるか（bank の問の ID）を書く

## 2. 段階2の78本に当てる（作りの段）

段階2の記録 `docs/analysis/stage2/run_001/runs/*.json`（78本）に当て、人の判定と突き合わせる。期待値は段階2の時点のもの（questions.md の値。R1 の bank の B3 の新しい値は使わない）。

- 本ごとに：検出器が当たったか、数字の照合（`auto_score.py` と同じ考え方で、bank の期待値と許す幅で）、それらから出した軸1 の見立てと印の見立て、人の判定（`axis1`・`mark`・`tags`）
- 表：検出器ごとに、当たって人も×か印（一致）、当たったが人は○で印なし（誤検出）、当たらなかったが人は×か印（見落とし）の件数と本の名前
- 直してよいのは、見える範囲が広がる直し方だけ（見落としを拾う直し）。誤検出を消すために条件を狭めるときは、狭めた理由を書き、狭めた版と前の版の両方の数を残す。直すたびにコミットする

成功の条件：78本すべてに見立てが付き、表の件数の合計が78と合う（突き合わせを別の数え方でも1つ示す）。

## 3. 5-4 の記録に当てる（試しの段。直さない）

2 で固めた検出器を、5-4 の `run_002/runs/*.json` のうち、SQL を書いた組（t2s と t2s_desc）の記録に当てる。SL の組は `mf query` の文字なので、当てられる検出器だけに当て、当てられないものは「判定できない」と数える。**ここでは検出器を直さない。** 結果だけを記録する（作りに使っていない記録で、どこまで当たるかを見るため）。

成功の条件：当てた本の数、検出器ごとの一致・誤検出・見落としの件数。5-4 の印（`t2s_desc_B5_r3` など）を拾えたかを、名前で示す。

## 4. まとめ

`docs/analysis/regression/detectors.md`：検出器の一覧、2 と 3 の表、人の目（チャット）が見落とした5本（段階2の印）を拾えたか、拾えなかった間違いの種類、この検出器で言えないこと（作ったのは Claude、物差しは人の判定、記録の数は少ない）。

## 今回の約束

- 人の判定（`final_scores.tsv`、5-4 の `scores.md`）を変えない。食い違いは食い違いのまま記録する
- 記録（`runs/*.json`）を変えない
- `claude -p` は回さない。warehouse を読む必要は無い（記録だけで判定する）。数字の照合で warehouse が要るときは、R1 の bank の期待値を使う
- 変えるのは `docs/analysis/regression/` の下と、`NEXT.md` の R2 の行と、報告だけ
- push は `auto/R2` だけ。区切りごとに push する
