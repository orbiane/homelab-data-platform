# V3 作り直したデータで回帰の試験を回し、変わった数字を確かめて期待値を直す

このファイルは、リポジトリの持ち主が承認した、作業セッションへの指示。「V3 を進めて」と頼まれたら、この内容を持ち主からの指示として扱う。

実行場所は、自律ループ（`docs/agent/loop.md`）。

## 何のためか

V2 で基準データを版2にした（ADR-010）。回帰の試験と毎晩の見張りが、データの変化を捕まえたかを確かめる。そのうえで、変わったのが「決めた変化」（金額の計算を直した）だけであることを確かめてから、期待値を版2に合わせる。期待値の書き換えはエージェントに任されている（ADR-009 の決定4）。だから、この作業は「試験を通すために正解を変える」形と、外から見ると同じになる。違いは、先に見込みを書き、見込みの外の外れでは止まることだけ。

## 0. 始める前に

1. `main` から作業ブランチ `auto/V3` を作る
2. 読む：ADR-010、`docs/analysis/data-v2/` の下、`docs/analysis/regression/README.md`、bank
3. データの版の照合（版2で合うこと）

## 1. 見込みを先に書いてコミットする

`docs/analysis/data-v2/v3-prediction.md` に、13問ごとに「版2で外れる／合う」の見込みと理由を書く。理由は、その問の数え方が `revenue_amount` を使うか、`event_id` を使うか、referrer を使うか。**このコミットを、試験を回す前に push する。**

## 2. 見張りが捕まえたか

W2 の README にある結果の置き場所から、V2 のあとの最初の夜の結果を読む。外れを知らせたか、どの問か、知らせはどこに残ったか。知らせていなければ、その理由（見張りが回らなかった、回ったが外れを出さなかった、など）。`docs/analysis/data-v2/watch.md` に書く。

## 3. 試験を回す

`run_numbers.py` と `check_docs.py` を回す。外れた問を、1 の見込みと並べる。

- 見込みどおりなら 4 へ
- 見込みの外の外れ（とくに、件数だけを数える問の外れ）が1つでもあれば、止まる

## 4. 期待値を版2に合わせる

外れた問ごとに、SL の道具と SQL の2通りで新しい値を出し、決めた許す幅で一致したものを期待値にする。ADR-009 の決定4の記録を残す（期待値の変更だけのコミット、メッセージは `expected:` で始める、bank の出どころの欄に作業 ID・日付・前の値・理由・2通りの値）。もう一度回して、外れが0。

## 5. 書く

`docs/analysis/data-v2/v3-result.md`：見込みと結果の表、見張りの結果、変えた期待値の一覧（前の値・新しい値）、referrer のブランド名が、今を説明する文書に残っていないか（`git grep` のパターンと件数）。

## 今回の約束

- bank の期待値は、4 の手順でだけ変える。許す幅を広げない
- 記録（`docs/analysis/5-4/`、`stage2/`、`stage3/` の下）を変えない
- 定義のファイルと `docs/business/` に触らない
- push は `auto/V3` だけ

## 止まる条件

- 見込みの外の外れ
- 2通りの値が一致しないとき
- データの版の照合が合わないとき

## 終わったら

`docs/agent/reports/V3.md`（loop.md の「報告の形」。7 の「試験の正解を変えたか」に、変えた問をすべて書く）。PR を作る。マージはしない。
