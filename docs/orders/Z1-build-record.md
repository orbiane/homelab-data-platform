# Z1 ビルドの段の記録を集める（事実だけ）

このファイルは、リポジトリの持ち主が承認した、作業セッションへの指示。「Z1 を進めて」と頼まれたら、この内容を持ち主からの指示として扱う。

実行場所は、自律ループ（`docs/agent/loop.md`）。`NEXT.md` のほかの行が、すべて済み（PR がマージ）か、断られた（PR が閉じられた）ときに着手する。

## 何のためか

ビルドの段（ADR-009）が終わる。このあと、持ち主が出来上がったものを評価する（分析の段）。そのための材料を、散らばった記録から1か所に集める。**集めるのは事実だけ。評価・解釈・教訓は書かない。** 「難しかった」「うまくいった」と書かず、「何回試した」「何に止められた」と書く。解釈は人がする。

## 0. 始める前に

1. `main` から作業ブランチ `auto/Z1` を作る
2. `NEXT.md` の全行の状態を、`gh pr list --state all` で確かめる。済んでも断られてもいない行があれば、何もせずに止まる

## 1. 集める

`docs/analysis/build-record.md` に、次の節を作る。数字には、必ず出どころ（ファイルと行、PR の番号、コマンド）を添える。

1. **作業の一覧**：ID、作業、種類、PR の番号、作った日、マージした日（断られたものは閉じた日）、PR の中のコミットの数、変わったファイルの数
2. **予定と実際**：各報告の「3 予定と実際」を写す（作業 ID ごと）
3. **詰まった所**：各報告の「4 詰まった所」を写し、失敗の数・試した回数を数えた表にする
4. **止められた操作**：各報告の「6」と、ループの記録（`~/homelab-loop/logs/` の要約。読むだけ）から、権限の表に断られた呼び出しと、関所に止められた呼び出しの一覧。道具・対象・理由・作業 ID。数を、止めた仕組み（権限の表／ADR-007 の関所／ループの hook／git の hook）ごとに数える
5. **仮決め**：`docs/agent/provisional/` の全ファイルから、仮決めの一覧（番号、一言、ほかの案の数）。作業ごとの数。そのあとの作業で覆されたものがあれば、どこで
6. **試験の期待値の変更**：`git log --grep='^expected:'` と bank の出どころの欄から、変えた問・前の値・新しい値・理由・作業 ID
7. **費用と時間**：ループの記録の要約から、起動の回数、Claude を起こした回数、合計の時間、合計の `total_cost_usd`。作業ごとの内訳（分かる範囲。分からない所は「記録に無い」）
8. **仕組みの地図**：守りの層ごとに、何であるか、何を止めるか、それを確かめた試し（ファイルと件数）、知っている穴の番号。層は少なくとも：CLAUDE.md（お願い）、`.claude/settings.json`、`.claude/loop-settings.json`、ADR-007 の関所（道具の入口・コミットの入口）、ループの hook、git の個人情報の検査、GitHub の main の保護、PR のマージ
9. **知っている穴**：ADR-007 の H、ADR-008・009 の K、ほかの ADR と報告に書かれた穴の一覧。塞いだもの（いつ、どの PR）と、塞いでいないもの
10. **やらなかったこと**：`NEXT.md` の「やらないと決めたこと」と、断られた PR

## 2. 確かめる

- 1 の作業の一覧の行の数が、`NEXT.md` の行の数と同じ
- 報告のファイルの数が、マージされた作業の PR の数と同じ（違えば、どれが無いか）
- 本文の数字の一覧を作り、すべてに出どころがあることを示す（数えた件数）
- 評価の言葉が無いこと：「よかった」「失敗した」「難しかった」「うまく」「教訓」などの語を `grep` して、0件（または、写した報告の文の中だけで、その場所を一覧にする）

成功の条件：上の4つを、コマンドと出力で示す。
