# R3 回帰の試験 第3段：本物のエージェントで解き直す（R3a 条件、R3b 本番）

このファイルは、リポジトリの持ち主が承認した、作業セッションへの指示。「R3a を進めて」「R3b を進めて」と頼まれたら、この内容を持ち主からの指示として扱う。

実行場所は、自律ループ（`docs/agent/loop.md`）。R3a と R3b は別の起動・別の PR。**R3a の PR を持ち主がマージしたことが、条件の承認になる。** R3b は、承認された条件だけで回す（段階2と同じ「回す前に条件を書いて承認し、コミットする」）。

## 何のためか

段階3で定義を変えた（`ctr` を消し、`ctr_per_open` と `opened_count` を足した）。SL の道具を持つエージェントが、変えていない問で前と同じ答え方をするか（崩れていないか）、変えた問（B3）で新しい定義どおりに答えるかを、段階2と同じ会場で確かめる。採点は R1 の bank（期待値）と R2 の検出器で、機械で行う。

## R3a：条件を書く

作業ブランチ `auto/R3a`。`docs/analysis/regression/live_001/conditions.md` と、ハーネス（段階2の `docs/analysis/stage2/run_001/harness.py` を import して使う。段階3の `find_002/harness.py` が `find_001` を使ったのと同じ形）を書く。回さない（試しの1本だけは回してよい。数に入れない）。

条件に必ず書くこと：
- 組：`sl_mcp` だけ（段階2と同じ4つの道具）。13問 × 3回 ＝ 39本
- 段階2から変えるのは定義（段階3の変更）だけ。前置き（日付 2026-10-29 を含む）、会場の作り方、旗、止まる条件、伏せ方は段階2と同じ。Claude Code の版は今のものを1本ごとに記録する（段階2は 2.1.316。変わったことは言えない理由として書く）
- 採点：R1 の bank の期待値（B3 は新しい値）と、R2 の検出器。D1 は、持ち主が Q2 を決めるまで「未決」として数える
- **判定の線（回す前に決める）**：段階2で3回とも○だった問が、今回3回中2回以下なら「崩れた」。B3 は、3回とも新しい定義（`ctr_per_open`）で答えれば「追いついた」。検出器が新しく当たった本は、名前を全部書く
- 費用の見込み：段階2の `sl_mcp` の39本の `total_cost_usd` の合計を記録から数えて書く。上限はその2倍。上限を超えそうなら、その時点で止まる
- 言えないこと：Claude Code の版とモデルの中身が段階2から変わりうる。崩れても、定義の変更のせいか、版の違いのせいかは分けられない

成功の条件：`conditions.md` が上を満たす。試しの1本の記録（数に入れない）で、会場とハーネスが動くことを示す。
