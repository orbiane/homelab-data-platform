# P2 新しい題材：取り込み

このファイルは、リポジトリの持ち主が承認した、作業セッションへの指示。「P2 を進めて」と頼まれたら、この内容を持ち主からの指示として扱う。

実行場所は、自律ループ（`docs/agent/loop.md`）。

## 何のためか

P1 の設計（ADR-011、マージで承認）のとおりに、電力の需要と天気を、リポジトリの外に取り込む仕組みを作る。取り込みを何度やり直しても同じ結果になり、配る側が過去の値を黙って直したら気づける形にする。

## 0. 始める前に

1. `main` から作業ブランチ `auto/P2` を作る
2. 読む：ADR-011、`power/README.md`、`power/CLAUDE.md`

## 1. 作る

- `power/ingest/` に、取り込みの道具（電力・天気）。ADR-011 の範囲・間隔・置き場所のとおり。ネットワークへのアクセスは、この道具の中だけ
- 取り込んだファイルの一覧：`power/raw_manifest.tsv`（ADR-011 の欄）。取り直しで指紋が変わったら、前の版を消さずに新しい版を足し、一覧に「変わった」と書く
- 取り込みの道具の試し（`power/ingest/tests/`）：ネットワークを使わずに、手で作った小さなファイルで回るもの

## 2. 確かめる

1. ADR-011 の範囲をすべて取り込む。ファイルの数、合計の大きさ、年ごとの行の数を出す
2. もう一度、同じ取り込みを回す。一覧に重複の行が増えず、「変わった」も0件（その日のうちに配る側が直していなければ）
3. 過去の値の直しを、作り物で確かめる：一時ディレクトリに、1つのファイルの1つの値を変えた写しを置き、見つける道具がそれを「変わった」として拾い、どの時刻の値かを出す
4. 試しが通る

成功の条件：上の4つを、コマンドと出力で示す。`git status --short` と、足した行の中身で、リポジトリに生のデータの行が入っていないことを示す（一覧の行だけ）。

## 今回の約束

- 生のファイルと、行ごとの値は、リポジトリに入れない
- 相手のサーバーに優しく：ADR-011 の間隔を守る。失敗したら、すぐに何度も取り直さない（回数の上限は仮決め）
- 今の `dbt_project/` と基準データに触らない
- push は `auto/P2` だけ

## 止まる条件

- 取り込みの途中で、相手から断られた（アクセスの制限など）とき
- 2 の2回目で、行が増えたとき（2回直しても直らなければ）

## 終わったら

`docs/agent/reports/P2.md`（loop.md の「報告の形」）。PR を作る。マージはしない。
