# L1 レビュー役と、PR のコメントで持ち主の決めを受ける仕組みを足す

このファイルは、リポジトリの持ち主が承認した、作業セッションへの指示。「L1 を進めて」と頼まれたら、この内容を持ち主からの指示として扱う。

実行場所は、持ち主の機械の Claude Code で、**持ち主が見ている（承認の画面が出る）セッション**。権限モードは Manual。理由：ループの台本と権限の表（`.claude/` の下）を変える（止まる類）。L0 の PR がマージされてから始める。

## 何のためか

今は、ループの PR を確かめて「マージしてよいか」を言う役と、ループが止まったときに持ち主の答えを受けて記録する役を、リポジトリの外の会話が担っている。持ち主は、PR のたびにその会話と行き来している。これをリポジトリの中に移す（ADR-009 の決定8）。

- レビュー役：ループの PR を確かめ、PR にコメントを1つ残す（手順は `docs/agent/review.md`）
- 持ち主の決め：持ち主が PR に「決め:」で始まるコメントを書くと、次のループの回がそれを読んで記録し、同じ PR の続きを進める（手順は `docs/agent/loop.md` の「持ち主の決めを受ける」）
- 直し：レビュー役が「直しが要る」と書いた PR は、次のループの回が同じブランチで直す（同じ PR で2回まで）

持ち主の手間は、GitHub の画面で PR とレビューのコメントを読んでマージするか、「決め:」を1行書くだけになる。

## 0. 始める前に

1. `main` を pull し、作業ブランチ `owner/L1` を作る
2. 読む：`docs/agent/loop.md`、`docs/agent/review.md`、ADR-008、ADR-009、L0 の PR で入った `agent/loop/` と `.claude/loop-settings.json`、`docs/agent/reports/L0.md`

## 1. レビュー役

- `agent/loop/review_checks.py`：`review.md` の1（機械の確かめ）。PR の番号を受け取り、表を出す。`selftest` を付ける（変わってはいけない場所の変更、`NEXT.md` の変更、報告の見出しの欠け、`expected:` でないコミットでの bank の変更、個人情報の行、のそれぞれを、使い捨ての clone の作り物で拾うこと）
- `agent/loop/review_prompt.md`：`review.md` の2をモデルに頼む文
- `.claude/review-settings.json`：レビュー役の権限の表。Read・Glob・Grep と、`git diff`・`git log`・`git show`・`gh pr view`・`gh pr diff` だけ。`gh pr comment` も Edit・Write も Bash の書き込みも入れない（コメントは台本が出す）。ADR-007 の hook は入れたまま
- `run.py` に足す：ループの1回のあと、`auto/*` の開いた PR のうち、先頭のコミットにまだ「レビュー:」のコメントが無いものを、1回に3つまでレビューする。モデルの返事に1行目を付けて `gh pr comment` で出す。上限：1つのレビューで10分

成功の条件：`review_checks.py selftest` が通る。L0 の試しの PR（または、使い捨てに作った試しの PR）に、1回だけレビューのコメントが付く。同じ先頭のコミットで2回目を回しても、コメントが増えない。

## 2. 持ち主の決めを受ける・直しを受ける

- `pick.py` に足す（決める規則は loop.md の「次の1件の選び方」のとおり。モデルに選ばせない）
  1. ループの開いた PR に、ループの最後のコミットより新しい「決め:」で始まるコメントがあれば、その ID を選び、同じブランチで続ける
  2. 次に、最新のレビューが「直しが要る」で、その PR での直しがまだ2回未満なら、その ID を選んで直す。PR の本文の1行目が「途中」の PR も、ここで選んで続ける（同じ PR で3回まで）
  3. どちらも無ければ、今までどおり新しい行を選ぶ
- `prompt.md`（ループへの頼み）に、続きのときは決めのコメントかレビューのコメントを渡し、loop.md の手順で進めるよう書く
- 「決め:」は、コメントの1行目の先頭にあるものだけを数える。「レビュー:」で始まるコメントの中の「決め:」は数えない

成功の条件：`pick.py selftest` に、決めのコメントがある場合・直しが要る場合・直しが2回済んだ場合・レビューのコメントの中に「決め:」が紛れた場合を足し、通る。

## 3. 試し

使い捨ての PR（`auto/L1-trial`。中身は報告のファイル1つ）で、次を順に示す。終わったら PR を閉じ、ブランチを消す（持ち主の承認の上で）。

1. レビュー役がコメントを1つ付ける
2. 持ち主が「決め: 試し」と書いたあと、`run.py --dry-run` が `L1-trial` の続きを選ぶ
3. 試しの PR の本文に「レビュー: 直しが要る」を書いた別のコメントを足しても、レビュー役のものでなければ数えないこと（数える規則は、台本が付けた1行目の形と、台本が出したコメントの記録で決める。決め方は仮決めしてよい）
