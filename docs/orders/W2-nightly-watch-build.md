# W2 毎晩の見張りを作る

このファイルは、リポジトリの持ち主が承認した、作業セッションへの指示。「W2 を進めて」と頼まれたら、この内容を持ち主からの指示として扱う。

実行場所は、自律ループ（`docs/agent/loop.md`）。**作るのはリポジトリの中のファイルまで。** 持ち主の機械への据え付け（定時の仕組みへの登録、Airflow の再起動など）は W3（持ち主の見ているセッション）。

## 何のためか

W1 で、回帰の試験を毎晩回す案を比べ、推す案を1つ出した。その PR のマージが、推す案の承認。その案のとおりに作る。毎晩の `dbt build` が通っても、数字が変わったことには誰も気づかない。それを次の朝に気づけるようにする。

## 0. 始める前に

1. `main` から作業ブランチ `auto/W2` を作る
2. 読む：`docs/analysis/regression/nightly-proposal.md`（W1 の推す案）、`docs/analysis/regression/README.md`、`airflow/dags/`、`agent/loop/README.md`
3. W1 の推す案が、マージされた `main` の `nightly-proposal.md` に1つ書いてあることを確かめる。無ければ止まる

## 1. 作る

- 推す案のとおりに、見張りの本体（回帰の試験の数字の層と文書の層を回し、結果を残し、外れたら知らせる）を作る。置き場所とファイルの名前は仮決めしてよい
- 定時の仕組みの雛形（launchd の plist、DAG の足し方など、推す案による）を、リポジトリには雛形だけ置く。ホームの絶対パスとユーザー名を書かない
- `README.md`：据え付け方（W3 の手順）、止め方、外し方、結果の置き場所、外れたときの知らせが届く場所
- `docs/decisions/ADR-012-nightly-watch.md`：選んだ案、理由、選ばなかった案（W1 から写す）、知っている穴（見張りが回らなかった夜に誰が気づくか、など）

## 2. 確かめる

- 今のデータで1回回し、すべて合う（外れ0）ことを示す
- わざと外れを作る：一時ディレクトリに bank を写し、1問の期待値だけ変えたもので回す。外れを知らせる道筋が動くことを示す（本当の知らせを送る道なら、送り先が一時的な試しの場所になるように切り替えて試す。切り替え方は仮決め）
- 毎晩の `dbt build` の時間（JST 02:50〜03:15）に warehouse を開かない作りになっていることを、コードの該当の行で示す
- warehouse に書き込まないことを示す（読むだけで開いている行）

成功の条件：上の4つを、コマンドと出力で示す。

## 今回の約束

- 定時の仕組みに登録しない（`launchctl` は使えない）。Airflow のコンテナを動かさない
- 変えるのは、見張りの本体と雛形、README、ADR-012、報告、`docs/agent/provisional/W2.md` だけ。推す案が `airflow/dags/` に新しいファイルを足す案なら、足すのはよい（既存の DAG は変えない）
- push は `auto/W2` だけ

## 止まる条件

- W1 の推す案が、止まる類（守りそのもの・権限・GitHub の設定）を変えないと作れないとき
- 同じ条件で2回直しても通らないとき
